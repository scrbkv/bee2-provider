# Testing Bee2 Provider

## Build and run

```sh
git clone --recurse-submodules https://github.com/scrbkv/bee2-provider.git
cd bee2-provider
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
    -DBEE2_PROVIDER_BUILD_TESTS=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Select another OpenSSL installation with `OPENSSL_ROOT_DIR` and, for tests
using the OpenSSL command-line tool, `BEE2_OPENSSL_EXECUTABLE`. The `openssl`
executable and runtime `libcrypto` must belong to the selected OpenSSL
installation. Configure the loader search path where necessary.

Run the regression or STB groups separately:

```sh
ctest --test-dir build -L regression --output-on-failure
ctest --test-dir build -L stb --output-on-failure
```

## Test categories

| Category | Verification |
| --- | --- |
| STB known-answer tests | Fixed published BELT, BASH, HMAC, BRNG, PBKDF and BIGN examples; independent expected outputs |
| EVP integration | One-shot and streaming ciphers, authenticated decryption, MAC/HMAC, KDF, randomness, cipher padding/CTS, key agreement and transport |
| Key serialization | BIGN-256/384/512 named and explicit parameters; SPKI/PKCS#8; DER and PEM; ordinary and encrypted keys; OpenSSL STORE |
| PBES2 | STB PBKDF2-HMAC-HBELT/BELT-KWP DER parameters, password rejection and decode iteration limit; OpenSSL-native PBES2/AES compatibility |
| Negative inputs | Wrong lengths, invalid modes and tags, malformed DER/PEM, unsupported parameters and state transitions |
| Interoperability | Direct Bee2 checks and bidirectional fixed/boundary/pseudorandom comparisons with the separate `bee2evp` engine |
| Isolation/concurrency | Independent OpenSSL library contexts, multiple provider instances and concurrent EVP use |

The STB reference-to-test map is in [STB algorithms and test vectors](STB_COVERAGE.md).
Tests of published ciphertexts are intentionally distinguished from
round-trip and two-interface comparisons. Expected KAT outputs must not be
generated by the implementation under test.

## `bee2evp` interoperability

Use a dedicated OpenSSL installation with a functioning `bee2evp` engine:

```sh
cmake -S . -B build-interop -DBEE2_PROVIDER_BUILD_TESTS=ON \
    -DBEE2_PROVIDER_ENABLE_INTEROP=ON \
    -DBEE2_INTEROP_PROVIDER_OPENSSL=/opt/openssl/bin/openssl \
    -DBEE2_INTEROP_BEE2EVP_OPENSSL=/opt/bee2evp/bin/openssl \
    -DBEE2_INTEROP_BEE2EVP_LD_LIBRARY_PATH=/opt/bee2evp/lib \
    -DBEE2_INTEROP_BEE2EVP_OPENSSL_CONF=/opt/bee2evp/openssl.cnf
cmake --build build-interop --parallel
ctest --test-dir build-interop -L interop --output-on-failure
```

The matrix covers supported BELT modes, AEAD, KWP, digests, MACs and BIGN
keys/signatures/certificates. Fixed, boundary and deterministic pseudorandom
inputs are checked in both directions where an engine implementation exists.

## ASN.1 and PBES2 verification

`bee2_bign_codec_crypto` checks the DER `EncryptedPrivateKeyInfo` envelope,
PBES2/PBKDF2 algorithm identifiers and parameters, mandatory BELT-KWP-256,
12,000 iterations, 24-byte salt, malformed encodings and wrong passwords.
The Annex E profile requires `NULL` in both PRF and KWP parameter fields.
The published Annex E.5 wrapped BIGN private scalar is checked using the
public decoder, and authenticated wrapping of PKCS#8 DER is rejected as a
nonstandard payload. Native AES-128/192/256-CBC PBES2 is tested separately
using OpenSSL's ordinary PKCS#8 encoding and decoding interfaces.

The binary and PEM framing tests cover concatenated records and nonseekable
BIO input. ASN.1 negative tests mutate and truncate DER key encodings; they
also check invalid key scalars, public points and explicit curve fields.

## EVP contract and coverage

OpenSSL supplies valid provider contexts for callbacks and owns several API
arguments. Provider tests target inputs that callers can actually control:
cryptographic sizes, operation ordering, parameters, authentication and
output-buffer limits. Invalid memory ownership or allocation failure is
handled defensively by production code but is not simulated merely to force
coverage branches.

For source-level coverage, configure GCC with
`-DBEE2_PROVIDER_ENABLE_COVERAGE=ON`, build and run the complete CTest suite.
GitHub Actions publishes gcovr line/branch reports for the `src/` tree. Raw
percentages remain diagnostic; sanitizer results, published known-answer
values and supported API behaviors determine functional correctness.

GitHub Actions also exercises the native suite with ASan and UBSan and runs
builds for the pinned OpenSSL versions documented in [CI](CI.md).
